# RAG 调优工作台

后台 `/rag-tuning` 分为「检索调优」与「生成调优」。本次不修改小程序对话入口。

测试的检索范围默认「仅知识库」，不进行 Cypher 规划和 Neo4j 查询。可另选「仅知识图谱」（跳过智谱知识库）或「混合检索」。三种模式的来源开关只在本次请求中应用，不修改缓存或生产配置。单次、对话及批量测试使用页面当前模式；历史汇总按知识库与检索模式分组。切换模式时原测试标准须重新确认。

此功能需要更新后台前端、重启后台服务，并重新部署 `processKnowledge`。默认库测试使用新增 `rag.test.search`，指定知识库使用签名保护的 `rag.tuning.search`；后端验证云端返回的实际模式，旧云函数不会被静默当作纯知识库测试。

## 使用流程

1. 在「检索参数」保存公共知识库、召回、重排、上下文和图谱参数。云函数缓存最长 5 分钟；运行记录中的 `effectiveConfig` 是本次执行使用的快照，不能把后台刚保存的配置视为已经生效。
2. 「单次测试」可仅检索，也可检索后进行多轮对话。每轮根据当前问题重新检索；回答携带最近 12 条历史消息。当前版本不做追问改写，追问应写清实体对象。
3. 在结果中查看前 K 条证据、候选资料、完整生成上下文、数据源诊断和配置快照。模型初评提供相关性等级、原文短引文、证据点支持资料及充分性说明；初评仅为建议。
4. 人工确认相关性与证据覆盖后保存复核；可将标注带入测试用例编辑器。一次检索得到的资料池不能自动视为完整标准集合。
5. 测试集支持新增、编辑、删除、JSON 导入导出和最多 100 个问题的串行批量检索。浏览器离开页面或点击停止时在当前题结束后停止。不是离线后台作业。
6. 每次运行保存当时的测试标准、配置、来源、上下文和标注。修改标准不会改写历史结果，需重跑使用新标准。页面展示最近 30 条，当前批次可单独导出全部结果。
7. 「生成调优」可调整模型、温度、输出预算及提示词，并重跑固定上下文。生成实验参数保存到独立实验配置，不会覆盖小程序生产生成参数。相同运行记录只保留最近一次生成，比较回答前先导出记录。

## 不同智谱知识库的测试

页面顶部「目标智谱知识库 ID」可选择历史 ID，也可直接输入新 ID，留空使用云函数默认知识库。输入即时绑定本次测试，无需按回车确认。输入仅对测试生效，不修改生产知识库。ID 须属于当前后台/云函数智谱 API Key 的可访问范围。仅选择“仅知识图谱”或“混合检索”时才会调用 Neo4j；知识库测试默认跳过图谱。

用例支持保存 `knowledgeId`。批量测试可选择按各用例保存的 ID 运行，或整批使用页面上方目标 ID。运行和导出记录同时保存请求 ID 与云端确认的实际 ID，历史页按知识库分别展示统计。片段评估 ID 包含知识库范围，避免不同库中的同名片段混淆。

切换目标库时，原库的完整标准及无答案标签不能直接移用；用例指定的库与本次实际库不一致时，这些指标回到待标注状态，证据点文本可以继续作为检查清单。公平比较两个库应为各库确认相关资料标准。

为防止普通小程序调用者任意访问同一服务账号下的其他库，覆盖 ID 通过专用 `rag.tuning.search` 云函数 action 传递。后台生成绑定问题、K、知识库 ID 和短有效期的 HMAC 签名，云函数核验后才接受覆盖。公开的 `kb.hybrid.search` 和 `kb.zhipu.search` 不接受来自数据字段的知识库覆盖。

后台与云函数需设置相同的至少 32 字符 `RAG_TUNING_SHARED_SECRET`；留空时可复用已有 `STREAM_SHARED_SECRET`。密钥只在服务端使用。未配置时默认库测试仍可运行，指定 ID 的测试返回明确配置提示。

## 评估口径

评估单位为稳定的片段/图谱事实 ID，不以排名或文档标题单独充当 ID。K 为 1–20。评估列表为所选检索范围内的前 K 条证据。仅知识库为文档，仅图谱为图谱事实；混合模式先文档后图谱，不是独立融合排序器的评测。候选结果为智谱最终返回、尚未经过文档阈值和上下文块数过滤的列表，不代表供应商内部全部候选。

| 指标 | 计算方式与前提 |
| --- | --- |
| Precision@K | 前 K 条中相关资料数 / K。所有返回资料须有确认标签，或用例明确声明完整标准；不足 K 条按缺失位置无命中处理。 |
| Recall@K | 命中的标准相关资料数 / 全部标准相关资料数。只在标准完整且有相关资料时计算。 |
| MRR@K | 第一条相关证据排名的倒数。单问题为 RR@K，汇总求均值为 MRR@K；未完全标注则待评估。 |
| nDCG@K | 相关等级为 0 无关、1 背景相关、2 直接支撑；增益 2^grade−1，折扣 log2(rank+1)。需要完整标准。 |
| 证据覆盖率 | 人工确认覆盖的必需证据点数 / 全部必需证据点数。未检查与明确零覆盖区分存储。 |
| 无答案判断 | “无证据”作为无答案判断的代理信号，与用例 noAnswer 比较；未知答案状态不计分。不是模型回答层面的拒答准确率。 |
| 无答案误召回率 | 在确定无答案的用例中，返回非空证据的比例。 |
| P95、空结果率 | 延迟包含后台到云函数的往返，不含记录写库、生成和评审。P95 包含失败；空结果率排除失败与降级。 |
| 成本 | 记录回答/评审上游提供的 usage；未提供检索账单或单价时，金额保持未知，不伪造零成本。 |

检索失败、已选择的图谱检索失败、双语部分失败、未知降级以及所有检索源关闭不进入正式质量指标。已确认只有 rerank_cooldown / rerank_unavailable 回退、知识库请求全部成功时，仍可人工评分及模型初评；回退未重排、部分重排回退、正常重排、主动关闭重排分别分组统计。历史记录在读取时按此规则重算，无需修改原记录或重新检索。无相关资料的问题 Recall/nDCG 不定义，保留空值。模型评分永远不会自动写成金标准。人工复核可以计算 Precision/MRR；Recall/nDCG 始终以用例中的完整标准为准。

最近 30 次描述统计可能混合不同配置与问题集，不可直接作 A/B 结论。公平比较应固定问题集、知识库版本、K、标准资料和上下文预算。知识库版本是人工填写的标记，目前供应商接口未提供内容版本快照；无法据此保证供应商资料没有变化。

生成使用生产链路返回的完整上下文，可能包含前 K 条以外的图谱资料；工作台显式展示这个范围差异。生成质量应另行检查忠实性、完整性与引用，不与检索指标混为一项。

## 管理 API

所有接口位于 `/api/rag-tuning`，使用现有后台 Bearer JWT。`admin` 可执行写入和模型调用，`viewer` 仅可读取。执行接口有独立限流，单次检索/生成/评审需为客户端配置约 120 秒超时。

检索调用在 `callFunction` 的第二个参数中显式设置 90 秒超时（SDK 默认仅 15 秒），覆盖混合检索的 55 秒执行预算与启动/传输开销，并关闭自动重试以避免重复执行耗时检索。调用超时记录 `errorDetail` 的阶段、SDK 错误码与原始信息；超时修复仅需更新并重启后台 Node 服务。

| 方法与路径 | 功能 |
| --- | --- |
| GET /settings | 读取生成实验默认值和模型白名单 |
| PUT /settings | 保存 `{ generation: { model, temperature, maxTokens, systemPrompt } }` |
| GET /cases | 最新 100 个测试问题 |
| POST /cases | 创建/更新用例；更新需 `id` |
| DELETE /cases/:id | 删除测试用例，保留历史运行 |
| POST /retrieve | `{ query, k, retrievalMode?, knowledgeId?, caseId?, batchId? }`，retrievalMode 可选 knowledge（默认）、graph、hybrid；默认库调用 `rag.test.search`，指定 ID 调用签名保护的 `rag.tuning.search` 并保存运行 |
| GET /runs | 最近 30 个运行摘要与带有效样本数的统计 |
| GET /runs/:id | 完整运行及现场计算的正式指标 |
| PUT /runs/:id/review | `{ grades: { [evaluationId]: 0\|1\|2 }, coveredPoints: null\|[0,1], note }` |
| POST /runs/:id/judge | 生成待复核初评，验证 JSON、ID 和引文确实在提供给模型的文本中 |
| POST /chat | `{ runId, query?, generation?, messages? }`，使用检索记录的上下文生成回答 |

用例 JSON 示例：

```json
{
  "query": "填写真实用户问题",
  "knowledgeId": "",
  "category": "跨文档问题",
  "corpusVersion": "2026-09-09",
  "noAnswer": null,
  "referencesComplete": false,
  "references": [],
  "evidencePoints": ["适用条件", "实验依据"]
}
```

`noAnswer` 为 null（未知）、false（应有答案）、true（确定无答案）。`references` 为 `{ "id": "结果中的 evaluationId", "grade": 2 }` 数组。

## 运行与部署

### 稳定性与报告优化

- 自动评估页显示完成、失败和空结果计数，可筛选异常项；检索失败和模型失败分别重试，成功初评会复用，不重复扣模型额度。
- 同一浏览器页签刷新后可恢复上次最多 500 条记录。页签仅缓存问题、参数和记录编号，证据与评分重新从后台读取；关闭页签后仍可在后台历史查找已保存记录。本功能不在关闭浏览器后继续派发请求。
- 报告默认显示 Precision、MRR、覆盖率，其余指标可展开。模型估算与已确认指标分开统计；按知识库、K、重排状态、模型分组，可只比较共同有效问题；覆盖率额外要求证据点一致，避免将不同标准直接相比较。
- 初评采用唯一的引文编号输出格式，限制输入资料总预算，针对格式错误和截断最多纠正一次。记录包含总模型调用次数、所有成功调用的 Token 用量、耗时和截断情况。不存在上游用量数据时不填零。
- 初评接口直接返回保存后的完整记录，减少额外读取；人工复核携带所见初评版本，版本过期会提示重读，避免误确认新评分。
- 模拟 UI 测试验证了批量分数、失败状态与刷新恢复；真实 CloudBase + 智谱测试覆盖三类问题，最后一题在统一引文格式后重试成功，均验证保存、重新读取和重复调用跳过。

### 初评保存失败排查

若真实后台出现 `Cannot create field 'coverage' in element {judge: null}`，原因是 CloudBase 将普通对象更新展开为嵌套字段写入，无法在原值为 null 的字段下创建子字段。运行记录的 judge、review、generation、judgeAttempt 等对象现在通过 `db.command.set` 整体替换该字段，保留同一记录的其他字段，并清除旧失败状态。需更新并重启后台服务；失败记录可直接重新初评。

2026-09-14 本地后台连接真实 CloudBase 和智谱后，以“砷资源化利用主要有哪些途径？”验证检索、初评保存及重新读取均成功：返回 4 条资料，Precision@5 模型估算 0.8、MRR 1、证据覆盖率约 0.667。这是单题诊断结果，不代表整库质量。`tools/rag-live-check.cjs` 可对本地 3108 端口执行同样的真实诊断，会产生测试记录并消耗模型额度，不输出认证令牌。

### 简化自动评估入口

“RAG 调优 → 检索调优 → 自动评估”为默认入口。输入问题（每行一题）或导入 TXT / JSON，输入知识库 ID 后点击“开始自动评估”；最多 100 个问题、5 个知识库，默认 K=5，仅查询知识库。多个 ID 使用同一批问题和 K，尽量复用首次成功初评的证据点；已有标准按各自知识库匹配。高级参数、测试集维护和历史抽查入口保留在其他页签。

缺少证据点时，后台先根据问题自动拆解证据点，再进行带原文依据的模型初评。Precision@K、MRR 和证据覆盖率可显示模型估算；存在人工标准时优先显示已确认值。模型估算不回写正式指标。Recall/nDCG 无完整标准不计算，无答案指标无答案性标注不计算，费用无上游计费信息不计算。JSON 对象支持原测试集字段；字符串数组和 TXT 不需要手工标注。

本批报告支持 PNG 对比图和 JSON 数据导出，按知识库及实际重排状态分组，每个指标显示有效样本数；缺少数据留空，失败项不会按零分计算。不同样本数或不同证据点标准的组仅供描述，不应直接据此认定某个知识库更好。当前报告保留在页面内，运行记录持久化到后台历史。批量运行时须保留页面，关闭页面不能继续派发下一题。

### 批量模型初评与待抽查

在“检索调优 → 检索测试 → 测试集与批量评估”运行问题集，然后进入“批量初评与待抽查”，选择记录并点击“批量模型初评”。支持按知识库、状态及当前批次筛选，展示最近 100 条记录。初评调用由浏览器逐条推进，离开页面后在当前请求结束时停止；已完成和失败状态保存到后台，可选择未完成记录继续或重试失败项。遇到鉴权、权限或限流错误会停止。

初评分为返回资料的平均相关等级除以 2，仅用于筛查，不写入 Precision/Recall 等正式指标。低于 60%、无直接证据、证据点覆盖不全、内容截断或与标准分歧的记录优先显示；也可随机选中筛选范围内 20% 的待抽查记录（向上取整），逐条打开复核。全部证据完成标注、证据点完成检查并保存后进入“已复核”；重新初评会重新进入待抽查。批量调用消耗已配置模型的额度。

本项功能只需更新管理后台前端构建并重启后台服务；不增加云函数改动。

- 复用后台 CloudBase 凭据；服务账号需允许调用 `processKnowledge`，并读写 `rag_eval_cases`、`rag_eval_runs`、`rag_eval_settings`。集合在首次写入时创建。评估数据仅供管理后台访问，不应为小程序客户端开放读取权限。
- 后台生成与初评使用已有 `ZHIPU_API_KEY` / `BIGMODEL_API_KEY`，模型限制沿用 `ZHIPU_ALLOWED_MODELS`。不向浏览器发送密钥。
- 更新后台前端构建与 Node 服务，并部署本次修改的 `processKnowledge`，使云端返回实际配置与候选结果，并正确传播重排/双语降级状态。旧版云函数会在界面提示无法核验参数版本。
- 自动化接口集成测试用内存数据库与显式模拟上游，不调用在线知识库。另行执行的真实服务诊断及配置变更见下文。
- `npm test` 包含评估指标及真实 Express 路由集成测试；`npm run check` 检查 JavaScript 语法；前端在 `web-admin/client` 下运行 `npm run build`。

### 2026-09-15：知识库内容评估六指标与折线报告

- 检索调优分为知识库内容、检索方法、嵌入模型三个方向，生成调优保持独立。检索方法复用现有召回与重排配置；多检索器自动实验、嵌入模型切换与重建索引尚未接入。
- 知识库内容评估显示 Recall@k、Precision@k、MRR、NDCG@k、Hit Rate、上下文相关性。先逐题计算，再对各库有效问题等权平均；保留 K、重排状态、评审模型分组，默认仅比较共同有效问题，并显示各指标样本数。
- 单题 Hit 为是否至少命中一条相关证据（0/1），平均后为 Hit Rate。单题倒数排名平均后为 MRR。健康的空检索在 Precision、MRR、Hit Rate 中计零，检索失败仍排除。上下文相关性为所评返回证据相关等级（0/1/2）的平均值除以 2，属于片段相关性代理指标，空证据不定义。
- 自动初评增加 autoReferencePool=true：对返回证据和已保存候选资料去重后最多 40 条统一打分，总输入正文预算 18000 字，保存 LLM 相关性参考标准及理由、引文。候选池标准不会覆盖人工完整标准；Recall/NDCG 模型值只衡量可见候选池，不能解释为全库指标。参考池可在复核弹窗查看，JSON 导出保留原始记录与标准。
- 图表可切换六指标聚合折线与指定指标的逐题趋势；缺失数据断线，支持 PNG 和 JSON 导出。各指标有不同含义，折线用于比较各库在同一指标上的差异。
- 此次更新只涉及管理后台前后端；需要重新构建前端、重启后台服务，不需要额外修改云函数。本地模拟验证不代表线上知识库质量验证。

### 2026-09-17：五组检索生成回答对比

入口：检索调优 → 五组回答对比。A直接回答，B文档RAG，C文档+图谱，D文档+专家规范，E文档+图谱+专家规范。支持1–20道问题、TXT/JSON字符串数组导入、统一生成参数、独立评审模型、可选人工参考答案。

每题先创建不可变实验配置，再生成公共评审标准、获取知识库和混合检索快照。B/C/D/E共享知识库快照里的前K条文档；C/E只从混合快照取图谱事实，避免文档结果不同造成混杂。文档正文每条最多2000字，图谱每条最多1000字，保存的实际证据会用于生成和评审；此窗口是控制变量实验，不等同于生产完整上下文链路。只有D/E注入按问题命中的专家规范。专家规范不是文献证据，未命中时明确展示。

各组生成与评审分阶段持久化；共享证据与标准保留，不因重试重新生成。图谱失败时A/B/D可先生成，所有组等待图谱准备成功后用统一证据盲评，避免先后评审标准变化。盲评输入不含组别标签，但回答措辞和引用可能间接暴露使用的证据。结果均为模型估算，不作为人工金标准。

指标先逐题计算再等权平均，默认只统计五组均已评审且回答未截断的题目；不同知识库、K、生成参数、模型与单价配置分别分组。专业正确率=正确结论/可判断结论；工况适用性=满足的工况项/可判断工况项；引用支持率=有支持的引用结论/可判断的带引用结论；无依据结论比例=无支持结论/可判断支持性的结论（越低越好）；回答覆盖率=覆盖点/全部必答点。无法判断排除并保留分子分母，无引用的引用支持率不定义，拒答不能伪造正确率。原文引用、引用ID、完整评分点与资料原文依据由服务端校验；每次结构化模型输出最多纠正一次。

记录生成/评审每次请求耗时、调用次数、上游usage和按用户输入的人民币/百万Token单价计算的费用估算。标准制定与共享检索的开销单独报告，不重复分摊进五组。图谱内部规划调用量、检索账单无法完整获得，端到端总费用为未知；未提供usage或单价不填零。柱状图可切换五项质量指标以及生成/评审耗时、调用次数、Token量和模型费用，支持PNG/完整JSON导出。

API位于 `/api/rag-tuning/answer-tests`：GET/POST根路径为历史/创建；GET `/:id`读取记录；POST `/:id/prepare`准备；POST `/:id/variants/:group/generate`生成；POST `/:id/variants/:group/judge`评审。使用现有管理员鉴权与限流，数据保存到`rag_answer_experiments`。批量由浏览器推进，关闭页面不继续派发；可恢复本页实验或读取最近30题历史。已完成阶段幂等复用，服务重启后未结束阶段保留10分钟保护期再重试。多进程同时执行同一实验未使用数据库事务锁，应保持管理服务单实例运行。

### 五组实验推荐默认值

前后端共用`web-admin/shared/answerDefaults.json`：温度0.1、输出上限4096 Token，基础提示词要求中文回答、结论与依据、事实/推断区分、缺失工况说明、真实资料编号引用和不执行资料内指令。五组使用相同基础提示词，不将D/E专用专家规则提前复制到所有组。可一键恢复推荐参数与提示词。人工参考答案保持留空，由模型按题生成标准；只有获得真实核验材料后才填写。官方价格页本次未成功读取，单价保持未知，不用0冒充已核实免费价格。

## 五组向量相似度实验

检索调优新增独立页签，输入问题和标准答案（或关键词文本），复用 A–E 五组共享证据生成。标准答案不会注入生成提示词。实验模式为 embedding-3-cosine-v1，与既有实验历史隔离。

评分调用智谱 embedding-3（2048维），以生成答案与标准答案的余弦相似度除以标准自身余弦（约1），乘100展示。保留负相似度，不冒充事实正确率。长文本按2400 UTF-8字节完整分块，以字节数加权平均向量；截断回答留空。记录评分模型、算法版本、用量及原始答案，支持JSON导出、历史读取和失败后续测。页面关闭后不再派发后续阶段。需构建前端并重启后台服务；使用后台 ZHIPU_API_KEY 或 BIGMODEL_API_KEY。
