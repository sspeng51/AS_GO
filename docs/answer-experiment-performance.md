# 五组实验执行优化

评分仍为 analytic-100-v2，正常每题仍为五次生成、一次标准制定、一次集中评审。未改变组别依赖、证据截取或评分公式。

- 后台默认两题同时执行，每题最多三组同时生成。进程内所有五组实验的模型调用共享四路上限，避免题目并发乘以组别并发造成过载。
- 文档和图谱独立检索并行，失败时等在途任务结束后保存。图谱不可用时保留可用组，恢复后沿用原回答并统一评审。
- 云函数中并发请求复用在途的 schema 读取；缓存失败不会保留失败的 Promise。未缓存检索结果，也未跳过图谱规划或重排。
- 连接重置等连接错误最多自动重试一次；超时、限流、鉴权错误不自动重试。评分先恢复本地有效结果，再仅补评缺失组，最多一次。持续失败保存诊断供继续操作。
- 标准制定输出预算从2048提高到4096，降低长标准截断风险；评审提示明确约束旧数据中频繁出现的多余右括号。不能保证外部模型永不输出无效JSON。
- 批次支持并发任务的暂停、断点恢复与活动快照。暂停等待在途阶段完成，不再领取新题；恢复不重新生成已有回答。
- 网页显示批次累计执行时间与逐题阶段时间，Excel增加阶段耗时和模型排队时间。阶段时间包括补试，不包括人工暂停间隔；不能把并行题目或共享检索相加当成整批耗时。旧记录缺失字段保持未知。

后台环境变量（修改后重启生效）：

| 变量 | 默认 | 有效范围 |
| --- | --- | --- |
| ANSWER_MODEL_CONCURRENCY | 4 | 1–8 |
| ANSWER_QUESTION_CONCURRENCY | 2 | 1–4 |
| ANSWER_GENERATION_CONCURRENCY | 3 | 1–5 |

全局上限为单Node进程上限，多个服务副本需按账户总配额分别配置。遇到429应降低并发再继续。

上线涉及后台服务、前端构建和 processKnowledge 云函数。不要在批次运行时强制重启；先暂停并等待在途阶段保存。实际加速比需要部署后以相同模型、题目和配置复测，单元测试不代表上游服务延迟。
